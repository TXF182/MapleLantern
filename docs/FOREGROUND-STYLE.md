# 灯台 · 前景图生成样式 v1

> 2026-11-23。目标不是“再画一套背景”，而是给人物层之上补一层**只在画面边缘出现的透明夹层**。
> 背景 512×256 是两帧图，不是一张横向双联画；前景必须沿用同一格式。

## 0. 先说结论：1.5.11 已把前景路径、选择器和自动切换全部拆开

已核对 `MapleLantern` 1.5.11 源码与图包：

| 事实 | 证据 |
|---|---|

## 1. 画布规格

| 项 | 值 |
|---|---|
| 文件 | PNG-32，RGBA，sRGB，非索引色 |
| 画布 | `512 × 256`，横向 2:1 |
| 帧 | `2` 帧，每帧 `256 × 256`；左帧 `x=0-255`，右帧 `x=256-511` |
| 静态前景 | 两帧必须**逐像素完全一致**；`animation: "idle"` 下不会闪烁 |
| 动态前景 | 最多 2 帧循环；两帧都要满足下面的安全区，不能一帧透明一帧遮人 |
| Alpha | 必须是真 Alpha；`alpha.min()=0`、`alpha.max()=255`；`alpha=0` 的像素 RGB 必须清零，避免白边 |
| 透明证明 | 不能拿“白底/棋盘格/PNG 后缀/全不透明 RGBA”当透明 |

## 2. 人物安全区（每帧）

以 `base-classic` / `base-slender` / `base-head` 的帧内 alpha 包围盒为参考：人物主体大致在 `x=78-229`。前景按更保守的框取：

| 区域 | 范围（每帧） | 规则 |
|---|---|---|
| **绝对安全区** | `x = 86-237`，`y = 0-255` | **alpha 必须全部为 0**；不得有任何像素、阴影、雾气、渐变、光晕 |
| 左侧主带 | `x = 0-85` | 上传包实测装饰带 `x=32-85`；可放门框、树干、砖柱等主前景，80-100% 不透明 |
| 右侧窄带 | `x = 238-255` | 上传包实测装饰带 `x=238-247`；只放薄边：帘边、灯罩边、藤尖、棚角，60-100% 不透明 |
| 顶部 | 仅左右带，`y=0-47` | 可放墙檐、树枝、帘头；**不得横跨中央** |
| 底部 | 仅左右带，`y=208-255` | 可放地毯边、草叶、石阶；**不得横跨中央** |

- 当前口径来自上传包 88 张的逐列实测：中央 `x=86-237` 全透明，左右装饰带分别到 `x=85` / `x=238` 起。`validate_foreground.py` 的默认参数为 `SAFE_X0=86`、`SAFE_X1=238`（右边界不含）。
- 旧文档写的 `x=64-243` 会切掉左带、压到右带，已废弃；样图 4/4 与上传包 88/88 都按新口径通过。

- 左右各给人物留约 **14-15px** 余量；这不是“人物一定只有 78-229”，而是当前标准体型的安全基线。发型、翅膀、触手、怀孕等异常姿势可能超出；上线前必须用该姿势的全角色实机截图复核，必要时把安全区收窄到 `x=60-247`。
- **中央不得用 10-30% 的半透明雾/尘来“补气氛”**；半透明同样会盖住人物。需要空气感时，只放在左右边带内。
- 一张前景的不透明像素建议 **15-25%**，硬上限 **30%**；超过就说明画面开始回到“背景图”而不是“边缘夹层”。

## 3. 画面内容

**只允许**：

- 贴近镜头、从画面外进入的边缘物件：门框、墙角、树干、树根、藤蔓、蕨叶、砖柱、铁艺灯柱、遮阳棚边、窗帘边、屋檐、石阶、地毯边、草叶、碎石。
- 物件必须“有前后关系”：近景物件比背景暗 10-20%，受光面有一道 1px 亮边；光源方向与背景一致（默认左上）。
- 2D 像素/软像素风：1px 硬边，3-5 个主色，允许轻微抖动着色；像素颗粒与现有 88 张背景同密度。

**禁止**：

- 完整房间、墙面、地板、天空、街道、森林、第二套场景；
- 人物、动物主体、家具主体、大件道具；
- 文字、UI、Logo、水印、边框、暗角、整幅渐变、白色蒙版、棋盘格；
- 把一张 `background1` 图直接当前景；那一定是全画面不透明；
- 用“景深虚化”把中央也糊上一层半透明——虚化只能发生在边缘带内。

## 4. 五个前景槽怎么分工

| 槽 | Z | 职责 | 允许区域 | Alpha 建议 |
|---|---:|---|---|---|
| `foreground1` | 300 | 左侧主前景：门框/树干/砖柱 | 左侧带 `x=0-85` 全高 | 80-100% |
| `foreground2` | 305 | 右侧薄边：帘边/灯罩/藤尖/棚角 | 右侧带 `x=238-255` | 60-100%，可选 |
| `foreground3` | 310 | 顶部角：屋檐/树枝/帘头 | 左右带 `y=0-47` | 60-90% |
| `foreground4` | 315 | 底部角：草叶/碎石/地毯边 | 左右带 `y=208-255` | 70-100% |
| `foreground5` | 320 | 近景虚焦/尘点/飞叶 | 仅左右边带，低透明度 | 10-35%，可选 |

- 同一地点同时开 **不超过 3 层**；同一张图不要 5 个槽重复叠。
- 自动前景只接管 `foreground1`，`foreground2-5` 留给玩家手动叠加；它与自动背景共用同一份地点名单和同一套地点判断，两个开关可分别启用。

## 5. 生成模板：必须“带背景参考”，不能只写文字

只写“暖木色/森林/城镇”这类文字描述，模型会自己发明一套配色，贴上去就会突兀。正确做法是**把对应背景的单帧作为参考图传入**，让模型先读背景，再画前景。

### 5.1 先做背景色卡（每张背景约 1 分钟）

| 项 | 从背景里读什么 | 例子（home.png） |
|---|---|---|
| 主色 | 出现面积最大的 4-5 个颜色 | 暖奶油 `#E8D3AE`、胡桃木 `#7A4A2E`、深棕 `#3A2418`、苔绿 `#4F6B3F`、砖红 `#8A4A3A` |
| 光源 | 光从哪边来、暖/冷 | 左上窗光，暖白 |
| 阴影色 | 暗部用的颜色，不是纯黑 | 暖棕 `#5A3A28` |
| 高光色 | 亮部用的颜色，不是纯白 | 暖奶油 `#F2DFC2` |
| 线宽/颗粒 | 1px 硬边还是软边；颗粒密度 | 1px 深棕硬边，细颗粒 |
| 材质 | 背景里已经出现的材质 | 木、布、陶、植物 |

### 5.2 背景联动版提示词（复制后替换【】）

```text
参考图是【背景名】的 256×256 单帧背景，只作为配色、光源、材质、线宽和颗粒的参考；不要修改参考图，也不要把参考图里的家具/房间重画一遍。
请生成一张独立的前景图层：1:1 正方形、透明背景、PNG 带真实 Alpha，只画从画外伸入的边缘物件，中央必须完全空。

【本次主题】……
【左侧主物件】……（占画面左侧约 25%，贴左边缘，从画外伸入）
【右侧薄边】……（只占画面右侧约 5%，极窄的一条）
【顶部角】……（只在左上/右上角）
【底部角】……（只在左下/右下角）

背景色卡：
- 主色：……（只允许用这些颜色及其明暗变体）
- 光源：……（方向、色温）
- 阴影色：……（不用纯黑）
- 高光色：……（不用纯白）
- 线宽/颗粒：……（与背景一致）
- 材质：……（只出现背景里已有的材质）

硬约束：
- 中央约 70% 宽、全高 100% 透明：不能有任何像素、阴影、雾气、渐变、光晕、尘点、颗粒、虚化。
- 顶部/底部只在左右角，不横跨中央；物件只露出局部，不画完整门/树/柱子。
- 只使用背景色卡里的颜色；最多 1 个点缀色，且必须是背景里已有的色相。
- 前景整体明度比背景低 10-20%，饱和度低 10-15%；阴影用背景阴影色，高光用背景高光色，不用纯黑/纯白。
- 近景可比背景大 1.2-1.5 倍，但透视方向与背景一致；不要反向透视。
- 物件与画面边缘之间可带 1-2px 暖棕接触阴影，但不能延伸到中央。
- 2D 像素/软像素风，1px 硬边，3-5 个主色，轻微抖动；不透明像素 15-25%，最多 30%。
- 不要画完整房间、墙面、地板、天空、街道、森林全景、人物、动物、家具主体、文字、UI、Logo、水印、边框、暗角、整幅渐变、白底、棋盘格。
- 输出：1536×1536 或 1024×1024 透明 PNG 一张；只生成单帧，不要拼成左右两帧；不要输出 512×256。
```

> 这里的 1:1 是**生成源图**；最终仍要缩到 `256×256`、硬清中央 alpha、复制成 `512×256` 两帧，不能直接把方图塞进图包。

### 5.3 生成后必须做“叠图验收”

不要只看前景单图。把前景以 100% 不透明度叠到对应背景上，检查：

1. **眯眼测试**：眯眼后前景和背景是否像一个场景？如果前景像贴纸/剪贴画，重做。
2. **25% 测试**：把前景透明度降到 25%，它应该几乎融进背景；如果仍然跳出来，说明对比/饱和度太高。
3. **色相测试**：前景里出现的颜色，是否都能在背景色卡里找到？超过 1 个新色相就重做。
4. **明暗测试**：阴影是不是暖棕/背景阴影色，高光是不是背景高光色？出现纯黑/纯白就重做。
5. **边缘测试**：有没有白边、发光边、贴纸描边？有就重做。
6. **安全区测试**：中央 `x=86-237` alpha 是否全 0？跑 `validate_foreground.py`。

通过标准：叠图后看不出“两张图拼的”，只看到一个有前后关系的场景；单看前景则只是一些边缘碎块。

### 5.4 批量策略：不要 1 套硬套 88 张

- 先把 88 张背景按“色系 + 光源 + 材质”聚成 8-12 个家族（暖室内、冷森林、砖城镇、石教堂、湿地/海岸、矿洞、工业、幻想……）。
- 每个家族选 1 张代表背景，生成 2-3 个前景变体，叠到家族内所有背景上验收；不合格的单独重做。
- `home`、`school`、`forest`、`town` 这类高频地点单独生成，不用家族通用图。
- 不要用同一套前景硬套全部背景；这是“突兀”的根源。

## 9. 1.5.11 已落地的四处

1. **`src/deco-core.js` 路径分源**
   - `LIBRARY_DIR = "img/decorations/ml/background1"`、`FOREGROUND_DIR = "img/decorations/ml/foreground1"`，`folderDir(folder)` 按前缀分流。
   - 背景 2-4 仍共用 `background1`，前景 1-5 共用 `foreground1`，不再共用背景库。
   - `safeImagePath` 只接受同类型目录；旧 `foregroundN` 路径改写到前景目录，背景图不会写进前景槽，反之亦然。
   - `imagePath` 按 `layer.folder` 取图。
2. **`src/deco-panel.js` 选择器分源**
   - `pickerSource` 按 `layer.folder` 设置；打开前景层时只列 `foreground1`。
   - `loadThumb` / `setImage` / 缩略图渲染都按当前 `state.pickerSource` 取图，手选前景 1 会关闭自动前景并恢复玩家原图。
   - 图库头部显示当前来源（背景 1 · background1 / 前景 1 · foreground1）。
3. **`imagepack/boot.json` + `pack-image.ps1`**
   - `imgFileList` 现有 105 条 `background1` + 105 条 `foreground1`，总 210 条。
   - 打包器分别校验背景 105、前景 105、总数 210、文件名一一对应，保留确定性 zip（mtime 1980、正斜杠、回读）。
4. **版本与包**
   - 1.5.11 图库包为 `MapleLantern-ImagePack-1.5.11.mod.zip`，不再覆盖 1.5.10。
   - 自动前景只接管 `foreground1`，`foreground2-5` 仍留给玩家叠加；若以后要 5 层全自动，需另扩目录与图库。
